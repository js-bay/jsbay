# JsBay Harmony SDK

Create an `Engine` and use its values from one ArkTS Worker. Production hosts should keep the engine off the UI ability thread; the Worker example under `examples/` is the recommended pattern. Owner-thread observability: `getMemoryUsage()`, `runGc()`, and `setEventHandler`. Same-process native faults still terminate the host process — see `docs/host-isolation.md`.

Create an `Engine` and use its values from one ArkTS Worker. Close owned values explicitly; callback values are borrowed and only live during that callback. Call `retain()` inside the callback to keep a value after it returns. Create engines with `Engine.create(instanceId)`; the `Engine` and `Value` constructors are private.

## Owner Worker and multi-instance hosts

Pin each instance id to one dedicated ArkTS Worker for its whole lifetime. The native bridge records the creating thread id and raises `JsBayStatus.WrongThread` if Engine or Value APIs run elsewhere. Do not send `Engine`, `Value`, or their N-API wrappers to another Worker, and do not create many engines on the UI/main thread of a Worker that also renders.

## CDP debugging

Call `engine.inspectorStart(0)` from the Engine owner Worker to start the bundled CDP HTTP/WebSocket listener and receive its selected port. Call `engine.inspectorStop()` from that Worker before `close()`. Both QuickJS-family builds expose Chrome DevTools breakpoints, stepping, and paused-frame evaluation.

The host application's `module.json5` must request `ohos.permission.INTERNET` to bind the listener. Expose the returned app-local port with `hdc fport tcp:<forwarded-port> tcp:<app-port>`, then run `node tests/inspector/e2e.cjs --host 127.0.0.1 --port <forwarded-port> --debugger-flow` on the development host. The owner Worker must continue processing debugger control work while execution is paused. Do not use a paused debugger command to run ordinary application tasks.

Prepare a device test app with `node tests/harmony-sdk/prepare-inspector-hap.cjs <new-directory> [HAR]`. It creates a HAP project with the public SDK dependency, network permission, owner Worker, and a Stop button that closes the Engine before terminating the Worker. Configure signing locally, install dependencies in its `entry` directory with `ohpm install`, then build with `hvigorw --mode module -p module=entry@default assembleHap`. Install and launch the app, read the selected port from the `JsBayCDP` log tag, and forward that port before running the protocol test. Remove the forwarding rule after testing.

For host-side protocol checks, build the N-API consumer with `tests/harmony-sdk/run_native_consumer.sh`, then run `JSBAY_HARMONY_NODE=<addon> node tests/harmony-sdk/inspector_consumer.cjs`. This exercises the same native bridge and core from a Worker; device verification also requires the Harmony SDK and its debugging transport.

The C ABI `jsbay_engine_request_interrupt(instanceId)` may run on an independent native thread. The ArkTS `requestInterrupt()` instance method still needs a wrapper available in the current Worker; it cannot interrupt a synchronous evaluation that is blocking that same Worker.

`Value.string()` decodes the engine's UTF-8 bytes with ArkTS `util.TextDecoder` and preserves embedded NUL and Unicode. JavaScript throws remain `JsException` with their original `value`. `describeAndClose()` reads and consumes that value; if `toString` throws, it closes both values and returns `"JavaScript exception"`. It reports borrowed, stale, and wrong-thread failures instead of hiding them. `JsBayStatusError.status` and `.code` identify C ABI failures; its constructor accepts `(status, code?)`, and `JsException` accepts an owned `Value`.

`bindSync` passes an opaque lossless `bigint` request ID, borrowed callback values, and a finite timeout. Forward the ID to independent native work and complete it with `jsbay_sync_complete`; do not schedule completion on the blocked owner Worker. `Engine.completeSyncString` / `completeSyncBytes` / `rejectSync` are the data-only ArkTS entries for another Worker's own N-API environment. `completeSyncBytes` takes `ArrayBuffer` / TypedArray / DataView (opaque octets; no UTF-8 check). Keep the ID as `bigint`; converting it to `number` may lose precision. Use `setAdmissionClass(0|1)` with Hide/Show when pairing suspend with BACKGROUND/FOREGROUND quota preference.

## Shutdown, execution budgets, and value diagnostics

`postScript(source, filename, callback?)` copies a script into the core owner-thread FIFO. `postFence(callback, sealShutdown?)` completes after preceding submissions and their immediate microtask checkpoints; it does not wait for future timers or another host transport. Accepted submissions report completed, exception, or cancelled exactly once while the environment remains alive. A rejected submission returns `false` without calling its callback; the host must propagate that rejection when reporting delivery or shutdown success. Synchronous `evaluate` remains available.

Start graceful shutdown with `Engine.beginShutdown(instanceId, generation, milliseconds)`. The first positive grace period establishes a monotonic deadline that repeated calls cannot extend. Stop external producers, let in-transit host messages reach the owner, then post a sealing fence through the same transport. Successful fence admission seals new submissions and fresh synchronous VM entries while accepted work finishes. `Engine.shutdownStatus` reports open, closing, sealed, drained, or cancelled. Drained confirms this queue's progress; the platform adapter must still terminate its Worker and confirm exit. Keep an independent host timer for a blocked Worker or a producer that never resolves.

Use `Engine.cancel(instanceId, generation)` for a shutdown request sent from a different Worker. Obtain `generation` from `Engine.snapshot(instanceId)` before handing the token to another Worker. The request is persistent for that engine generation: `clearInterrupt()` cannot resume it, and an old generation token cannot cancel an instance that reused the same id. Cancel is a shutdown operation, not a pause or a recovery mechanism.

`setExecutionBudget(milliseconds)` sets a deadline for each outer VM entry. `0n` disables it. The budget covers evaluation, timer callbacks, Promise draining, executable Value operations such as `call`, getters, and `toJson`, and synchronous bridge waits through the earlier of the active budget and a manual execution limit. Nested JavaScript entries retain the outer deadline. It cannot preempt arbitrary native code that has not returned to an engine interrupt or synchronous-wait boundary.

`getValueUsage()` reports owned wrapper diagnostics. `live` is the number of owned values that still have a Harmony wrapper. When a wrapper is garbage-collected without `close()`, `abandoned` increases but its core handle remains until engine shutdown; GC does not release it into the VM. `peak` is the largest observed `live` count for this engine generation. Close owned values explicitly and use the counters to find values that escaped that discipline. Borrowed callback values are not included.

A Harmony Worker is a thread boundary inside the host process. It does not isolate native faults: an abort or memory-safety failure in the bridge or JavaScript backend can still terminate the host process.

The SDK automatically connects the JavaScript event loop to its owner Worker through N-API TSFN and one platform timer. The event loop owns its clock, deadlines, and wakeups. `runLoop()` runs a blocking loop until `stopLoop()`; ordinary Worker integration needs no manual progress calls. `close()` cancels scheduled work before releasing the native engine, and environment cleanup detaches before disposing callback data.
